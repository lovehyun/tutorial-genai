# 케이스 3 — 클라이언트가 접속정보 제공, 서버는 프록시

```
클라이언트 ──[접속 DSN 을 세션에 제공]──▶ 서버(무자격증명) ──▶ 클라가 지정한 DB
```

- 서버는 **아무 자격증명도 갖지 않는다.** 어디에 붙을지는 **클라이언트가** 정한다.
- MCP 서버 = "네가 준 DB 에 쿼리해 주는" **범용 프록시 인터페이스**.

## 🔐 보안 핵심 — 비밀은 '툴 인자'로 받지 마라
`run_query(dsn, sql)` 처럼 DSN(비번 포함)을 **도구 인자로 받으면 LLM 컨텍스트·대화 전사에 그대로 남는다(유출).**
그래서 접속정보는 **세션 밖 채널**로 받는다:

| 전송 | 접속정보 전달 |
|------|----------------|
| **stdio** (이 데모) | 서버 띄울 때 **환경변수** `CLIENT_DSN` — `StdioServerParameters(env=...)` |
| **HTTP** | 접속 시 **헤더** (예: `X-DB-DSN`) — 연결마다 |

→ 도구 인자에는 오직 `sql` 만. 자격증명은 절대 흐르지 않는다.

## 실행
```bash
python ../init_db.py       # shop.db + hr.db 생성
pip install mcp
cd 3.client_supplied && python client.py
```
→ 같은 `server.py` 를 **shop.db** 로 한 번, **hr.db** 로 한 번 붙인다. 자격증명 0, 대상은 클라이언트가 결정.

## 기대 결과
- `shop.db`: `which_db` = products/orders/... → 상품 TOP3
- `hr.db`: `which_db` = departments/employees → 직원·부서 조인

## 언제 이 모델이 맞나 / 주의
- ✅ "아무 DB나 연결하는 범용 도구", BYO-DB(사용자가 자기 DB 를 가져옴).
- ⚠️ 서버가 **임의 대상에 붙으므로** SSRF/내부망 스캔 위험 → 실전은 **허용 호스트 화이트리스트**, 타임아웃, 읽기전용 강제.
- ⚠️ DSN 을 로그에 남기지 말 것(`which_db` 도 **스킴만** 노출). 헤더/환경변수는 전사에 안 남지만 서버 로그엔 남을 수 있다.
