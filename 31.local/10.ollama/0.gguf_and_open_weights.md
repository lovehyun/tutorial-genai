# 0. GGUF와 오픈 웨이트 — Ollama로 로컬 모델을 돌린다는 게 정확히 뭘 하는 건가

`5.qwen25`~`8.exaone40`을 따라 하다 보면 자연스럽게 드는 의문들 — "GGUF가 뭐지?",
"오픈 웨이트는 뭐지?", "왜 Qwen은 공식 Ollama 버전이 있는데 EXAONE 4.0은 없지?",
"공식 버전이 없으면 최신 모델은 대체 어디서 구해서 어떻게 돌리지?" — 를 여기서 한 번에 정리한다.
바로 앞 폴더(`8.exaone40`)에서 실제로 부딪힌 문제이기도 하다.

## 1. 모델을 학습하면 원래 어떤 형태로 나오나

LG나 Alibaba 같은 곳이 GPU 수백~수천 장으로 몇 주씩 학습을 돌리면, 그 결과물은
**"가중치(weights)"** — 신경망의 수억~수천억 개 숫자(파라미터)다. 이게 저장되는 표준 형태는:

- **safetensors**(요즘 표준) 또는 옛날엔 `.bin`(PyTorch pickle) — HuggingFace Hub에 올라오는 바로 그 파일들
- 보통 **FP16/BF16**(16비트) 정밀도 — 예: 70억 개 파라미터(7B) 모델이면 파일 크기가 대략 **14GB**
- 이걸 그대로 불러 쓰는 게 `31.local/1.transformers`, `3.huggingface`에서 쓴
  `AutoModelForCausalLM.from_pretrained(...)` 방식이다 — **원본 그대로, 가장 정확하지만
  가장 무겁다.**

## 2. "오픈 웨이트(open weight)"란

**학습된 가중치 파일을 누구나 다운로드해서 로컬에서 실행할 수 있게 공개했다**는 뜻이다.
GPT-4나 Claude처럼 API로만 접근 가능한("클로즈드") 모델과 대비되는 개념이다.

주의할 점 — "오픈 웨이트"가 "완전한 오픈소스"를 뜻하진 않는다. 아래 셋은 서로 다른 축이다:

| 축 | 의미 | 예 |
|---|---|---|
| **가중치 공개 여부** | 파일을 받아서 돌릴 수 있나 | Qwen(공개) vs GPT-4(비공개, API만) |
| **라이선스** | 받은 뒤 뭘 해도 되나(상업적 이용·재배포 등) | Qwen(Apache-2.0, 자유) vs EXAONE(비상업 전용) vs Llama(커뮤니티 라이선스, 일부 제약) |
| **학습 재현 가능 여부** | 학습 데이터·코드까지 공개했나 | 대부분 "오픈 웨이트"만 하고 데이터는 비공개(완전한 오픈소스는 아님) |

이 저장소에서 EXAONE을 계속 "비상업·gated"라고 표시해온 이유가 여기 있다 — 가중치는
받을 수 있지만(오픈 웨이트), 라이선스가 상업적 사용을 막는다(제약 있는 라이선스).

## 3. GGUF란 — "로컬 실행 전용 압축 파일 포맷"

**GGUF**(GPT-Generated Unified Format)는 `llama.cpp` 프로젝트가 만든 **단일 파일 포맷**이다.
모델을 학습하는 곳(LG, Alibaba)이 원래 내놓는 형태가 아니라, **로컬 CPU/GPU에서 빠르게
돌리기 위해 나중에 변환하는 형태**다.

- 가중치 + 아키텍처 정보 + 토크나이저 + 채팅 템플릿을 **파일 하나**에 담는다
- 보통 **양자화(quantization)**까지 같이 한다 — 16비트 숫자를 4비트 등으로 뭉개서 정확도를
  아주 조금 희생하고 용량·속도를 크게 얻는다. 예: 7B 모델이 FP16 14GB → **Q4_K_M 양자화로
  약 4~5GB**까지 줄어든다
- **Ollama는 내부적으로 GGUF만 쓴다** — `ollama pull qwen2.5:1.5b` 할 때 실제로 받는 게 GGUF
  파일이다

즉 순서는 이렇다: **학습(LG/Alibaba) → safetensors 공개(HuggingFace) → 누군가 GGUF로
변환+양자화 → Ollama 레지스트리에 올림 → `ollama pull`로 받음.**

## 4. 그 "누군가"는 누구인가 — 공식 vs 커뮤니티

GGUF 변환은 공개된 스크립트(`llama.cpp`의 `convert_hf_to_gguf.py`)로 **누구나** 할 수 있다.
그래서 Ollama 레지스트리에 올라오는 모델은 두 부류로 나뉜다:

| | 예 | 특징 |
|---|---|---|
| **공식 라이브러리** (`ollama.com/library/<이름>`) | `qwen2.5`, `qwen3.5`, `gemma2` | 모델 제작사(Alibaba, Google)나 Ollama 팀이 직접 변환·검증해서 올림. 품질 보증됨 |
| **커뮤니티 업로드** (`<사용자명>/<이름>`) | `ingu627/exaone4.0`, `sam860/exaone-4.0` | 개인이 스스로 변환해서 자기 이름으로 올림. **품질이 사람마다 다르다** |

`8.exaone40`에서 실측했듯, 커뮤니티 업로드는 채팅 템플릿(생각모드 태그·도구 호출 형식을
프롬프트에 심는 방식)을 업로더가 손으로 맞춰야 하는데, 이걸 틀리면 `ollama show`엔
capability가 멀쩡히 찍혀도 실제로는 동작이 이상해진다(`message["thinking"]`이 안 채워짐,
tool calling이 0/3으로 실패함 등) — **공식 라이브러리에는 이런 리스크가 훨씬 적다.**

## 5. 그럼 EXAONE은 왜 공식 라이브러리가 없나

Alibaba(Qwen)·Google(Gemma)·Meta(Llama)는 Ollama 팀과 직접 협력해서 공식 변환본을
올려준다. **LG는 (아직) 그렇게 하지 않았다** — 정확한 이유는 공개돼 있지 않지만, 정황상:

- EXAONE의 라이선스가 **비상업 전용**이라 범용 배포 파트너십과는 성격이 다르다
- LG AI Research는 HuggingFace(`LGAI-EXAONE/EXAONE-4.0-*`)에 공식 배포하는 것까지만
  하고, Ollama 같은 서드파티 런타임과의 공식 패키징까지는 아직 안 한 것으로 보인다

가중치 자체는 완전히 공개돼 있으니(오픈 웨이트), 그래서 개인들이 알아서 변환해 올린
`ingu627/`, `sam860/` 같은 비공식 버전만 존재하는 것이다.

## 6. 공식 버전이 없으면, 최신 EXAONE은 어디서 받아서 어떻게 돌리나

**진짜 원본(가장 정확·최신)은 항상 HuggingFace다** — LG가 직접 배포하는 곳.
`https://huggingface.co/LGAI-EXAONE` 에서 최신 버전을 확인할 수 있다. 여기서부터 로컬
실행까지 가는 방법은 난이도 순으로 세 갈래다:

### (A) 커뮤니티 GGUF를 그대로 받는다 — 가장 쉽지만 리스크 있음
`8.exaone40`에서 한 방식. `ollama pull sam860/exaone-4.0:1.2b` 한 줄이면 끝나지만,
**품질을 실제로 써보기 전엔 모른다** — 반드시 스모크 테스트(몇 번 호출해서 확인)를 해야 한다.

### (B) HuggingFace 원본을 `transformers`로 직접 돌린다 — 가장 정확, 가장 무거움
```bash
pip install transformers torch
```
```python
from transformers import AutoModelForCausalLM, AutoTokenizer

MODEL = "LGAI-EXAONE/EXAONE-4.0-1.2B"   # LG가 최신 버전을 여기 올린다
tokenizer = AutoTokenizer.from_pretrained(MODEL)
model = AutoModelForCausalLM.from_pretrained(MODEL)
```
`31.local/1.transformers`, `3.huggingface`에서 쓴 것과 완전히 같은 방식이다. **원본 그대로라
동작이 정확하다는 보장이 가장 크지만**, GGUF보다 용량이 크고(양자화 안 됨), Ollama 같은
편의 기능(`ollama run`, Modelfile)이 없어서 직접 코드를 짜야 한다.

### (C) 원본을 내가 직접 GGUF로 변환한다 — 가장 신뢰할 수 있는 "Ollama 방식"
커뮤니티 업로더를 못 믿겠고 Ollama의 편의성은 갖고 싶다면, **직접** 변환하면 된다:
```bash
git clone https://github.com/ggerganov/llama.cpp
cd llama.cpp
python convert_hf_to_gguf.py <LGAI-EXAONE 다운로드 경로> --outfile exaone4.gguf
./llama-quantize exaone4.gguf exaone4-q4.gguf Q4_K_M   # 양자화(선택)
```
그다음 `Modelfile`(이 폴더의 `4.modelfile/` 참고)로 감싸서 `ollama create`하면, **내가 직접
검증한 내 GGUF**를 Ollama로 돌릴 수 있다 — 커뮤니티 업로더의 실수 리스크가 없다.

### (D) 다른 로컬 런타임
Ollama가 유일한 선택지는 아니다 — **LM Studio**(GUI), **vLLM**(서버용, GPU 클러스터에 강함),
**llama.cpp**(Ollama가 내부적으로 쓰는 바로 그 엔진, 더 세밀한 제어) 등도 HF 원본 또는
GGUF를 그대로 받아 로컬에서 돌릴 수 있다. 이 저장소는 교육 목적상 Ollama로 통일했을 뿐이다.

## 정리 — 흐름도

```
학습(LG/Alibaba, GPU 수백 대)
   ↓
safetensors 로 HuggingFace 공개  ← "오픈 웨이트"는 여기서부터
   ↓
   ├─(A)→ 누군가 GGUF 변환+양자화 → Ollama 레지스트리 업로드 → `ollama pull` ← 이 폴더 대부분
   ├─(B)→ transformers 로 원본 그대로 로드                                    ← 31.local/1.transformers
   └─(C)→ 내가 직접 llama.cpp 로 변환 → 내 Modelfile → `ollama create`        ← 신뢰도 최고
```

공식 라이브러리(Qwen, Gemma, Llama)는 (A) 화살표를 제작사가 직접 책임지고 그어준 것이고,
EXAONE처럼 공식 라이브러리가 없는 모델은 그 화살표를 **누가 그었는지 반드시 확인해야
한다**는 게 `8.exaone40`의 실측이 보여준 교훈이다.
