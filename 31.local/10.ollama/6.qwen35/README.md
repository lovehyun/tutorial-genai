# 6.qwen35 — Qwen 3.5 의 새 기능: 생각 모드 · Tool Calling (Ollama)

**Qwen 3.5**(Alibaba, 2026-02 공개)는 [`../5.qwen25`](../5.qwen25)(Qwen 2.5)의 다음 세대다.
순수 한국어 NLP 태스크는 5.qwen25 와 구조가 같으니, 여기서는 **2.5에는 없던 두 가지**만 다룬다 —
생각 모드(thinking)와, "생각 모드가 있어야 도구 호출이 되는가"라는 흔한 오해.

## 핵심 개념부터

- **Qwen 2.5**: 생각 모드 자체가 없다. 항상 "즉답"만 한다.
- **Qwen 3.5**: 같은 모델 파일 안에서 `think=True/False`로 "깊게 생각하고 답하기"와
  "바로 답하기"를 매 호출마다 전환할 수 있다 — 버전을 통째로 바꾸는 게 아니라 옵션 하나다.
- **Tool calling은 둘 다 된다.** "추론 모델이라야 도구 호출이 가능하다"는 오해가 있는데
  사실이 아니다 — Qwen 2.5도 이미 native tool calling을 지원한다(`3.tool_calling.py`에서 실측).

## 준비

```bash
ollama pull qwen3.5:2b     # ~2.7GB, 예제 기본
pip install ollama
```
> 더 큰 태그(`qwen3.5:4b` 이상)로 바꾸면 생각 모드의 안정성이 더 좋을 수 있다 — 아래 관전
> 포인트의 "예산 부족" 문제는 작은 모델일수록 더 잘 재현된다.

## 예제

| 파일 | 내용 |
|---|---|
| `1.thinking_mode.py` | `think=True/False` 기본 사용법(내부 사고 과정 전체 출력 포함) + **생각 모드가 토큰 예산을 다 써버려 답을 못 내는 경우**를 실측으로 재현 |
| `2.thinking_mode_stream.py` | `stream=True`로 사고 과정을 실시간으로 지켜보기 — "멈춘 건가?"를 실측으로 해소 |
| `3.tool_calling.py` | Qwen 2.5 vs 3.5 tool calling 신뢰도·속도 비교 (5회 반복) |

## 관전 포인트 — 생각 모드는 공짜가 아니다

`1.thinking_mode.py`의 핵심 실측: 아주 사소한 산수 문제("17+26")에서도 이 모델은 생각을
과도하게 길게 하다가 `num_predict`(토큰 예산)를 사고 과정만으로 다 써버리고 **최종 답을
한 글자도 못 쓴 채 끝난 적**이 있다(`done_reason=length`, 답 = `''`). 예산을 늘려도(3000토큰)
매번 안전한 건 아니다 — 실행마다 "얼마나 오래 생각할지"가 확률적으로 달라지기 때문이다
(CPU에서는 3000토큰으로 성공했는데, GPU에서는 같은 3000토큰으로 실패한 경우도 실측됐다).

**실전 교훈**: 생각 모드를 켤 땐 `num_predict`/`max_tokens`를 넉넉하게 잡거나, 실패
(`done_reason=length` + 빈 답변)를 감지해서 예산을 늘려 재시도하는 로직이 필요하다.

**왜 이렇게 오래 생각하나 — 내부 사고 과정을 직접 열어보면 드러난다.** "17+26" 정도는 계산
자체가 사고 과정 셋째 줄에서 이미 끝난다("Calculation: 10+20=30, 7+6=13. Total = 43"). 그런데
그 뒤로 "혹시 말장난인가?", "숫자 퍼즐인가?", "시간 계산 문제인가?"를 거의 100줄 가까이 반복해서
의심하다가 맨 마지막에야 답을 적는다 — 예산을 다 잡아먹는 건 계산의 어려움이 아니라 **불필요한
자기검열 루프**다. 작은 모델일수록 "언제 생각을 멈출지" 판단이 서툴다는 뜻이다(`1.thinking_mode.py`
주석에 실제 사고 과정 발췌가 그대로 있다).

## CPU vs GPU 실측 비교

같은 코드를 CPU(로컬)와 GPU 서버(RTX 4070 Laptop, 8GB VRAM)에서 각각 돌려봤다 — 두 파일의
"참고: GPU 서버 실측" 주석에 원본 수치가 그대로 있다. 요약하면:

| | CPU | GPU |
|---|---|---|
| 생각 모드 OFF | 2.0초 | 7.5초(첫 호출, 모델 로딩 포함) |
| 생각 모드 ON | 52.7초 | 31.0초 |
| tool calling 평균(모델 로딩 후) | 수 초대 | 1~2초 |
| 예산 3000토큰 성공 여부 | 성공 | **실패**(런마다 다름) |

**GPU가 확실히 빠른 건 "생각 과정" 같은 계산량이 큰 작업**이고, 단순 즉답(OFF)이나 첫 호출은
모델을 VRAM에 올리는 로딩 비용 때문에 오히려 더 크게 보일 수 있다 — 그리고 예산 부족 문제는
하드웨어와 무관하게(CPU든 GPU든) 발생한다. "GPU면 다 해결된다"가 아니라 "GPU는 계산을
빠르게 해줄 뿐, 예산을 얼마나 줘야 하는지는 여전히 개발자가 판단해야 한다"는 게 핵심이다.
