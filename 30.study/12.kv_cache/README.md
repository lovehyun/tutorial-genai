# 12.kv_cache — 매번 처음부터 다시 계산하지 않는 이유

GPT류 모델은 토큰을 하나씩 이어붙이며 생성한다. 순진하게 하면 매 스텝마다 지금까지의 전체
문장을 처음부터 다시 계산해야 한다 — 그런데 과거 토큰들의 Key/Value는 한 번 계산되면 다시는
안 바뀐다(causal mask 때문에 미래 토큰이 추가돼도 과거엔 영향이 없다). 그래서 그걸 캐시해두고
새 토큰분만 계산하면 된다 — 그게 KV 캐시다. vLLM 같은 고성능 서빙 엔진의 메모리 관리가 사실상
이 캐시를 얼마나 잘 다루느냐의 문제다.

## 파일

| 파일 | 내용 |
|---|---|
| `1.kv_cache_demo.py` | 캐시 없이/있이 각각 80토큰 생성 → 스텝별 소요 시간 비교 + **결과가 완전히 동일함을 직접 증명** |

## 실행 (실측 결과)
```bash
pip install transformers torch matplotlib numpy
python 1.kv_cache_demo.py
```
```
캐시 없음: 총 2.842초 (첫 스텝 19.6ms → 마지막 스텝 48.0ms, 계속 느려짐)
캐시 사용: 총 1.161초 (첫 스텝 14.9ms → 마지막 스텝 17.5ms, 거의 그대로)
→ 속도 차이: 2.45배
→ 두 방식의 생성 결과 문장: 완전히 동일
```

## 관전 포인트
- **그래프가 핵심**: 캐시 없음(빨강)은 스텝이 갈수록 우상향 — 문장이 길어질수록 매번 처음부터
  다시 계산하니 느려진다. 캐시 사용(초록)은 거의 평평 — 새 토큰 1개분만 계산하니 문장 길이와
  거의 무관하다.
- **결과는 수학적으로 100% 동일하다** — 캐시는 근사치나 지름길이 아니라 "같은 계산을 다른
  순서로 하는 최적화"다. 실제로 두 생성 결과를 직접 비교해서 확인했다.
- 이 데모는 짧은 문장(GPT-2, 80토큰)이라 2.45배 차이지만, 실전 LLM(수십억 파라미터, 수천 토큰
  대화)에서는 이 차이가 수십~수백 배로 벌어진다 — 캐시가 없으면 애초에 실시간 응답이 불가능하다.
