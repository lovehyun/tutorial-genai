# 3단계 → 4단계 변경점

한 번 승인한 기능은 다시 묻지 않는다. 대신 **무엇을 위임했고 무엇이 바뀌었는지** 화면에 띄운다.

## 안 바뀌는 것

`../servers/` 전부 · `LOOP`/`run()`/`spawn()` · `JOBS` · `delegate_task` · 에이전트 분리 구조

함수 단위로 재보면 **3단계 함수 14개 중 9개가 한 글자도 안 바뀐다**:
`collect` · `delegate_task` · `list_jobs` · `make_checkpointer` · `mcp_config` ·
`new_job` · `public` · `run` · `spawn`

## 파일이 셋으로 나뉜다 (코드 변경 아님, 위치만 이동)

3단계까지 `app.py` 하나였는데 400줄이 넘었다. **각 파일이 '몇 단계에서 배운 것' 에 대응**하도록 나눴다.

| 파일 | 내용 | 4단계에서 바뀐 것 |
|---|---|---|
| `jobs.py` | 이벤트 루프 · 작업 저장소 · 워커 루프 · 로컬 도구 (3단계) | `AUTO_APPROVED` · `needs_approval` · `run_job` 두 줄 |
| `agents.py` | MCP 설정 · 체크포인터 · 에이전트 조립 (1~3단계) | **없음** |
| `app.py` | Flask 라우트 · DB 스냅샷 | 4단계 내용이 여기 모인다 |

라이브에서는 "3단계까지 배운 건 파일로 내려두고, 4단계에서 새로 배우는 것만 `app.py` 에 남깁니다" 로 넘어가면 된다.
`jobs.py` 안의 4단계 변경점에는 `# [4단계]` 주석을 달아 뒀다 — 그것만 찾으면 된다.

> 모듈 이름이 `worker.py` 가 아니라 `jobs.py` 인 이유: 워커 에이전트를 담는 전역 변수를
> 3단계와 같은 이름(`worker`)으로 유지하려고. 덕분에 `run_job` 본문이 3단계와 거의 같다.
> `jobs.py` 는 `agents.py` 를 import 하지 않는다(순환 참조) — `app.py` 가 `jobs.bind(worker)` 로 주입한다.

## app.py — 핵심 변경 한 줄

승인 대상을 고르는 조건에 자동승인 검사가 붙는다.

```python
# 3단계
risky = [c for c in calls if c["name"] not in SAFE_TOOLS]

# 4단계
def needs_approval(call):
    return call["name"] not in SAFE_TOOLS and call["name"] not in AUTO_APPROVED
ask = [c for c in calls if needs_approval(c)]
```

`AUTO_APPROVED` 는 **빈 집합으로 시작**한다. `[항상 승인]` 을 누를 때만 늘어난다.

## app.py — 추가

| 추가 | 하는 일 |
|---|---|
| `AUTO_APPROVED` | 자동승인된 도구 이름 집합 |
| `db_snapshot()` | 계정·권한·발송 기록을 DB 에서 직접 읽는다 |
| `/auto/<name>/revoke` | 자동승인 해제 → 다음부터 다시 물어본다 |

`decide` 엔드포인트가 `{approved}` 에서 **`{approved, always}`** 를 받는다.
`always=True` 면 그 도구를 `AUTO_APPROVED` 에 올린다.

```python
/jobs  (3단계)  →  /state   작업 + 자동승인 목록 + DB 현황을 한 번에
```

## index.html — 왼쪽 패널 추가

- 레이아웃 2단 → **3단**(`.layout4`): **왼쪽 패널** / 채팅 / 작업 패널
- 왼쪽 위 **⚡ 자동승인 목록** — 등록된 기능 + `해제` 버튼
- 왼쪽 아래 **🗄 DB 현황** — 계정 / 권한 / 발송 기록. 각 묶음이 **접기/펼치기**(접어도 개수는 보인다)
- 채팅창 아래 **작업 로그** — 워커가 부른 도구 내역. 역시 접기/펼치기, 기본은 접힘
  (3단계에서는 작업 카드 안에 있어서 오른쪽 패널이 금방 길어졌다 → 아래로 옮겼다)
- 승인 카드 버튼 2개 → **3개**: 승인 · **항상 승인** · 거부

> 1초마다 다시 그리므로 **펼침 상태를 JS 쪽(`dbOpen`)에 들고 있어야** 다시 그려도 안 접힌다.
> 내용이 그대로면 아예 다시 그리지 않는다(`dbCache`) — 깜빡임과 스크롤 튐 방지.

### `high` 배지는 무엇인가

접근 그룹의 위험도(`servers/store.py` 의 `GROUPS`)다. `prod-db` · `payroll` 이 high.
권한 목록이 길어졌을 때 **"저건 줘도 되나?" 싶은 것**이 눈에 띄게 하려는 장치다.
계획서의 ⚠️ 와 달리 **DB 에 저장된 데이터**라 LLM 이 관여하지 않는다.
다만 **표시만 하고 승인 로직에는 영향이 없다** — 아래 한계와 이어진다.

## 왜 패널이 필요한가

자동승인만 넣으면 그건 **가드레일을 끄는 것**이다.
무엇을 자동으로 넘겼고(자동승인 목록) 그 결과 무엇이 바뀌었는지(DB 현황)
볼 수 있어야 비로소 통제가 된다. 작업 로그에도 `⚡ 자동승인: create_account` 로 남는다.

> DB 현황은 **일부러 MCP 를 거치지 않고** DB 를 직접 읽는다.
> 에이전트가 '정말로' 바꿨는지는 MCP 밖에서 봐야 검증이 되기 때문이다.

## 자동승인의 단위 — 이 예제의 한계

여기서는 **도구 이름** 단위다. `grant_access` 를 자동승인하면
`prod-db` 든 `payroll` 이든 **전부 그냥 나간다.** 실습에서 직접 확인해 보라.

더 정교하게 가려면 (라이브 코딩 소재):

| 방식 | 예 |
|---|---|
| 도구 + 인자 조건 | `grant_access` 는 자동, **단 `risk=high` 그룹은 제외** |
| 유효기간 | 오늘 하루만 자동승인 |
| 횟수 제한 | 5회까지만 자동, 이후 다시 확인 |
| 감사 로그 | 누가 언제 왜 등록했는지 DB 에 기록 (지금은 메모리라 재시작하면 사라진다) |
