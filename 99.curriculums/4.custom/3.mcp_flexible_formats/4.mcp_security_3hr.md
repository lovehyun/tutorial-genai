# 4. MCP 실전 3시간 — Tool Calling·MCP 복습 + HITL·가드레일 (보안 특화)

모듈 ID(M0, M21 등)의 정확한 폴더/분량은 [`0.base.md`](0.base.md)의 모듈 카탈로그 참고.

**대상** MCP·tool calling을 한 번은 배웠고(복습으로 빠르게 훑는다), **"에이전트가 위험한 일을
못 하게 어떻게 막나"** — 사람 승인(HITL)과 코드 가드레일 두 가지를 집중적으로 다루고 싶은 경우.
[`1.mcp_practice_4hr.md`](1.mcp_practice_4hr.md)와 앞 두 섹션은 비슷하지만, 3번째 섹션부터
**라우팅/순차분기 대신 보안**으로 방향을 튼다.

**구성** `M0 → M0.5a+b+c(tool calling 복습) → M1(MCP stdio 개요 복습) → M21(HITL) → M22(가드레일)`

**전체 스토리라인 — "이미 배운 걸 복습하고, 위험한 순간을 어떻게 막는지로 넘어간다"**:
1. **tool calling 복습** — 빌트인 도구 호출(`llm-math`) → `@tool`로 직접 제작(LangChain 프로세스 안에 갇힘, 그래서 MCP가 필요했다는 걸 다시 떠올림) → 빌트인 `human` 도구(모르는 건 추측 대신 사람에게 되묻기) — 이게 3번 HITL로 가는 다리다: **되묻기(정보 수집)와 승인(허가)은 둘 다 "실행을 사람에게 넘긴다"는 같은 아이디어의 다른 형태**
2. **MCP 개요 복습** — `initialize→list_tools→call_tool` 첫 왕복을 다시 보고, `debug_proxy`로 그 아래 오가는 JSON-RPC를 확인
3. **HITL(사람이 막는다)** — 되돌릴 수 없는 도구(`delete_file`, `send_email`)를 실행 직전에 멈춰 사람에게 묻는다. 전부 물으면 승인 피로가 온다는 것도 직접 느낀다
4. **가드레일(코드가 막는다)** — 정중한 요청("오래된 파일 정리해줘")이 LLM을 거치며 위험한 인자(`rm -rf`)로 바뀌는 걸 직접 보고, 정규식 판정 코드가 그걸 실행 전에 막는 걸 확인

HITL과 가드레일은 **같은 문제를 다른 층에서 막는 두 안전장치**다 — 3번은 "사람이 최종 결정", 4번은
"코드가 자동으로 결정". 실무에선 이 둘을 같이 쓴다(가드레일이 1차로 거르고, 그래도 위험한 건 HITL로).

### 마무리 (2:55–3:00)

- **HITL vs 가드레일**: 가드레일은 "코드가 판정"(빠르고 결정적이지만 아는 패턴만 잡음), HITL은
  "사람이 판정"(느리지만 새로운 위험도 잡음). 실무는 **가드레일로 1차로 거르고, 그래도 위험군인
  도구는 HITL로 한 번 더 확인**하는 조합을 쓴다.
- 더 볼 자료:
  - 가드레일을 MCP 밖(일반 챗봇/RAG)까지 넓게 — [`2.langchain/11.guardrails/`](../../../2.langchain/11.guardrails/) (a/b 쌍 6종, 프롬프트 인젝션·PII·SQL 인젝션 포함)
  - HITL을 웹 UI로 — [`10.project/18.mcp_ops_assistant/`](../../../10.project/18.mcp_ops_assistant/) (M18, 승인→위임→자동승인 4단계 라이브 데모)
  - 계획 단위 승인(`3.plan_approve`), 대화형 비서(`4.interactive`) — [`5.mcp/4.langchain/6.human_in_loop/`](../../../5.mcp/4.langchain/6.human_in_loop/) 나머지 파일
