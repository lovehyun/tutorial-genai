# 챗봇 2 - 대화 히스토리

이전 대화 내용을 기억하는 챗봇 구현입니다.

## 핵심 개념

- 대화 히스토리를 `messages` 리스트로 관리
- 이전 대화 맥락을 유지하여 자연스러운 연속 대화
- 토큰 절약을 위한 히스토리 제한 (최근 N개만 유지) 또는 압축(요약)

## 예제 목록

`a`/`b` 쌍은 내용이 같고 **시간 측정 유무만 다릅니다**(`b`가 요청/응답 시간을 출력). 시간 측정은 초반
두 단계에서 한 번씩만 보여주면 충분해서, `app4`부터는 시간 측정 없는 버전 하나로만 진행합니다.

| 파일 | 설명 |
|------|------|
| `app_restapi.py` | REST API로 히스토리 관리 |
| `app2a_openailib.py` | OpenAI SDK로 전환 |
| `app2b_openailib_time.py` | 2a + 요청/응답 시간 측정 |
| `app3a_history.py` | 메모리 기반 대화 히스토리 |
| `app3b_history_time.py` | 3a + 요청/응답 시간 측정 |
| `app4_historylimit.py` | 히스토리 개수 제한 — 오래된 대화를 **버림**(pop) |
| `app5_history_summary.py` | 히스토리 요약 압축 — 오래된 대화를 **버리지 않고 요약**해서 남김 |

### app4 vs app5 — 버리기 vs 요약하기

둘 다 "히스토리가 `MAX_HISTORY_LENGTH`(10개)를 넘으면 어떻게 할 것인가"를 다루지만 전략이 다릅니다.

| | app4 (제한) | app5 (요약) |
|---|---|---|
| 넘치면 | 가장 오래된 메시지부터 **삭제** | 오래된 부분을 **LLM으로 요약**해서 시스템 메시지 1개로 압축 |
| 맥락 | 오래된 내용은 완전히 사라짐 | 요약된 형태로 계속 남아있음 |
| 비용 | 추가 API 호출 없음 | 압축 시점마다 요약용 API 호출 1회 추가 |

`app5`는 "실제로 오간 대화 전부"(`full_history`)와 "GPT에 지금 보내는 압축된 작업용 히스토리"(`conversation_history`)를
따로 들고 있어서, 압축 전/후가 어떻게 달라지는지 직접 비교해볼 수 있습니다.

- `GET /api/history` — 원본 로그 전체 (압축과 무관하게 실제로 오간 모든 메시지)
- `GET /api/history/compressed` — 지금 이 순간 GPT에게 실제로 전송되는 압축된 히스토리 (요약 메시지 + 최근 대화)

콘솔에도 압축이 일어날 때마다 "압축 전(원문) / 압축 후(요약)"이 함께 출력되니, 대화를 10턴 이상 이어가면서
지켜보면 요약이 어떻게 만들어지는지 눈으로 확인할 수 있습니다.

## 실행

```bash
python app5_history_summary.py
```
